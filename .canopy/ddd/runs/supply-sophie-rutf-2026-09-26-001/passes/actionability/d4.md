# Actionability cold derivation — d4

Derived only from the narration payload (features withheld). Cross-scene foundations are listed first because every scene depends on them. Nothing is assumed to exist already.

## Foundations (shared across scenes)

- **Models**
  - `Program(id, name)` plus `Program.buyer_of_record` FK to `Org` (the seed program is "Connect-RUTF", buyer "Dimagi"). `ProgramMembership(program, user)` controls who can read history.
  - `Tender(id, program FK, round_no, title, product, quantity, delivery_point, deadline, status[open|awarded|closed], published bool)`.
  - `Order/Shipment(id, tender FK, status[in_transit|delivered], expected_arrival date, paid bool)`.
  - `Quote(id, tender FK, supplier Org FK, unit_price, currency, freight_terms[included|excluded|not_specified], incoterm, lead_time_days, superseded_by FK self null, voided bool)`.
  - `Outreach(id, tender FK, supplier FK, sent_at, replied_at null)`.
  - `Revision(id, entity_type, entity_id, program FK, field_changes JSON {field: [old, new]}, sentence text, actor_user FK null, actor_kind[web|mcp_agent], agent_label e.g. "ACE (agent)", source_excerpt text null, idempotency_key unique null, reason text null, created_at, supersedes_revision FK null)`. It is append-only, and it is the single writer path for every mutation.
  - `OperationCall` wrapper `record_change(entity, changes, actor, via, source_excerpt=None, idempotency_key=None, reason=None)`. It de-duplicates on `idempotency_key`: a second call with the same key returns the existing revision and writes nothing.
- **Seed command** `manage.py seed_sophie_rutf`. It is idempotent and does the following:
  - Program Connect-RUTF with Dimagi as buyer, and user Sophie as a member.
  - Round 1: quote → award → shipment. On 2026-08-10 the ETA is set to 5 Sep (Sophie, web). On a later date the ETA changes 5 Sep → 19 Sep via MCP with agent "ACE (agent)", an excerpt and key `email:<msgid>`. The same key is replayed a second time and produces no new revision. The shipment is delivered and paid.
  - Round 2, created 2026-09-01 (after 20 Aug): open, 3 suppliers invited, 3 quotes created via MCP with AI actor, each missing a basis (freight not_specified with the email excerpt stating "freight included to Kano"; incoterm missing; currency/pack size missing). Two outreach rows have `sent_at` = today−15d and no reply.
  - At least 2 other programs, with other buyers, each owning an open published tender.
- **Test fixture** `sophie_rutf` pytest fixture that calls the seeder, plus `freezegun` set to 2026-09-26.

## Scene 1: Sophie reads where her program stands today

- Add route `GET /supply/?program=<id>` (or `/supply/p/<program_id>/`) with view `SupplyOverviewView` and a login + membership gate.
- Add header element `data-testid="supply-header"` rendering `"{program.name} · {buyer.name}, buyer of record"`.
- Add a table `data-testid="supply-overview"` with one `<tr data-testid="overview-row-{tender.id}">` per tender or order **filtered to `program=current`**. Columns:
  - stage (`data-testid="row-stage"`), derived as delivered+paid / in transit / open-awaiting-quotes / awarded.
  - waiting-on text (`row-waiting`), for example "waiting on quotes (1 of 3 replied)".
  - last changed (`row-last-changed`) = latest Revision across the tender and its children: `created_at` plus the actor name, or agent_label.
  - `row-stale` flag, shown when any Outreach has `sent_at <= now-14d and replied_at is null`, OR any active quote has a missing basis. The tooltip lists supplier names and quotes.
  - `row-ai-badge` ("AI"), shown when the latest revision has `actor_kind == mcp_agent`.
- Put stale and missing-basis logic in `supply/staleness.py::stale_reasons(tender, now)`. Missing basis = any of `freight_terms=='not_specified'`, `incoterm is None`, `currency is None`.
- Tests:
  - `assert "Connect-RUTF · Dimagi, buyer of record" in resp.text`.
  - Rows contain round 1 and round 2 and do not contain the other programs' tender titles.
  - `stale_reasons(round2)` includes both suppliers that have not replied and ≥1 missing-basis quote. `stale_reasons(round1) == []`.
  - The round 2 row has `row-ai-badge`. The round 1 row's last-changed actor text matches its latest revision.

## Scene 2: Sophie finds the day round 1's arrival slipped

- Add route `GET /supply/tenders/<id>/` (`TenderDetailView`). It shows the current-state panel `data-testid="tender-state"`, then `data-testid="timeline"`.
- The timeline aggregates Revisions for the tender, its quotes, award, shipment and payment, ordered by `-created_at`. It is rendered as `<li data-testid="timeline-item">` with `sentence` built by `revision_sentence(rev)`, for example `"ETA 5 Sep → 19 Sep"` from `{"expected_arrival": ["2026-09-05","2026-09-19"]}`, formatted `%-d %b`.
- Actor badge `data-testid="actor-badge"`:
  - Web revisions show the user's display name and no excerpt control.
  - MCP revisions show `agent_label` as a `<button>`, which opens `<details>`/popover `data-testid="source-excerpt"` with the `source_excerpt` text.
- MCP tool `supply_chain_shipment_update(shipment_id, expected_arrival, source_excerpt, idempotency_key)` routes through `record_change`.
- Tests:
  - Calling the shipment update twice with the same `idempotency_key` → `Revision.objects.filter(entity=shipment, field_changes__has_key="expected_arrival", actor_kind="mcp_agent").count() == 1`.
  - Page text count of `"ETA 5 Sep → 19 Sep"` == 1.
  - The first timeline item is the payment and the last is the first quote.
  - That item's badge text is `"ACE (agent)"`, and its excerpt element contains the seeded email text.
  - Web-actor items contain "Sophie" and no `source-excerpt` element.

## Scene 3: Sophie looks at her program as it stood on 20 Aug

- Add a header date control `<input type="date" name="as_of" data-testid="as-of-date">` in a GET form to the overview. The query is `?as_of=2026-08-20`.
- As-of reconstruction is `supply/history.py::state_as_of(program, date)`. It rewinds by applying, in reverse, every Revision with `created_at > end_of(date)` to current values ("rolled-back rewind"). Entities whose creation revision is after the date are excluded.
- When `as_of` is set:
  - Render banner `data-testid="as-of-banner"`: `"Viewing as of 20 Aug 2026 — "` + link `data-testid="back-to-today"` to the URL without `as_of`.
  - Suppress all write controls with the template flag `read_only=True`. POST handlers also reject when `as_of` is present (405/403).
- Tests:
  - `?as_of=2026-08-20` shows the banner text `"Viewing as of 20 Aug 2026"`.
  - The round 1 stage is "in transit" and expected arrival reads "5 Sep".
  - There is no `overview-row-{round2.id}`.
  - No elements match `[data-testid^="action-"]`.
  - `back-to-today` href == `/supply/?program=<id>`, and GET of it shows round 2 again.
  - Unit test: `state_as_of(...)` shipment `expected_arrival == date(2026,9,5)`.

## Scene 4: Sophie reads what each round 2 quote is missing

- Add route `GET /supply/tenders/<id>/compare/` (`TenderCompareView`).
- Comparability service `compare(tender)` returns `{ranked: [...], needs_info: [{quote, missing: [basis...], who_can_answer}]}`.
  - Each basis maps to words: `freight_terms` → "freight terms (who pays delivery)", `incoterm` → "delivery terms (Incoterm)", `currency` → "currency".
  - `who_can_answer` is the supplier contact name/org.
- Banner `data-testid="compare-banner"`. When `ranked` is empty, it reads `"None of the 3 quotes can be compared yet"`.
- Section `data-testid="needs-info"` with rows `data-testid="needs-info-{quote.id}"` showing the missing text (`missing-basis`) and `who-can-answer`. Show `ai-badge` when the quote's creation revision `actor_kind == mcp_agent`.
- Tests:
  - `len(compare(round2).needs_info) == 3`, `ranked == []`.
  - The banner contains "None of the 3 quotes".
  - Each needs-info row has non-empty `missing-basis` text containing a human word (not a field name like `freight_terms`) and the supplier name.
  - `ai-badge` count == 3 (all seeded via MCP).

## Scene 5: Sophie checks one AI-entered quote against the email and corrects it

- Add route `GET /supply/quotes/<id>/`, which shows quote fields and a timeline using the same component as scene 2.
  - The creation sentence is `"Quote recorded … (freight: not specified)"`.
  - The AI badge opens the `source_excerpt` containing "freight included".
- On MCP-authored revision lines where the viewer is a program member and not `as_of`, show buttons `data-testid="action-correct"` and `data-testid="action-void"`.
- Add route `GET|POST /supply/quotes/<id>/correct/`, a ModelForm over the correctable fields plus a required `reason` textarea.
  - On save, create a new Quote version with `supersedes` pointing to the old one, and set the old quote to `superseded_by=new`.
  - Record a Revision `actor_kind=web`, `actor_user=Sophie`, `reason`, and `field_changes={"freight_terms": ["not_specified","included"]}`.
  - Redirect to `/supply/quotes/<new_id>/`.
  - The new quote's timeline includes the old quote's revisions (lineage), so Sophie's correction sits above the AI's original entry.
- Add route `POST /supply/quotes/<id>/void/` with a reason. It sets `voided=True` and writes a revision.
- Tests:
  - An AI line has `action-correct` and `action-void`. A web line has neither.
  - The excerpt contains "freight".
  - POST correct with `freight_terms=included, reason="email states freight included"` → 302 to the new quote.
  - `new.freight_terms=="included"`, `old.superseded_by==new`.
  - The new page's timeline item 0 badge is "Sophie" with the reason, and a later item's badge is the AI label with "(freight: not specified)".
  - POST without a reason → form error, and no new Quote.

## Scene 7: Sophie awards round 2 and says why she will not wait

- `compare()` now ranks the corrected quote, because it has no missing basis. It is marked `provisional=True` because `len(needs_info) > 0`, and the row shows the `provisional-flag` "Provisional — 2 quotes still blocked".
- The ranked row gets `<textarea name="reason" data-testid="award-reason">` and a button `data-testid="action-award"`. These go in a `POST /supply/tenders/<id>/award/` form with `quote_id` and `reason` (required when provisional).
- Model: `Award(tender, quote, provisional bool, reason, awarded_by, awarded_at)`. Set `tender.status="awarded"` through `record_change`, with a web actor and the reason.
- On the overview, the stage for round 2 reads "Awarded (provisional)", and last-changed shows today's date and Sophie.
- Tests:
  - Before the award, the compare page shows the corrected quote in ranked with `provisional-flag`, and needs-info count == 2.
  - POST award with a reason → `Award.objects.get(tender=round2).provisional is True`, `awarded_by == sophie`.
  - POST without a reason while provisional → 400/form error.
  - The overview row for round 2 contains "Awarded", "provisional", today's formatted date and "Sophie".
  - After the award, the market no longer lists round 2 as open.
