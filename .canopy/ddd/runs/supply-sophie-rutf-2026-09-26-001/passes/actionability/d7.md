# Actionability cold derivation — d7

Derived only from the narration payload (features withheld). Nothing is assumed to exist beyond what the text states.

## Cross-cutting foundations (needed by several scenes)

- **Models (Django, labs DB):**
  - `Program(id, name, slug, buyer_of_record: FK Org)`, `Org(id, name)`, `ProgramMembership(program FK, user FK)`.
  - `Tender(id, program FK, number, title, product, quantity, quantity_unit, delivery_point, deadline, stage[choices: draft/open/awaiting_quotes/awarded/ordered/in_transit/delivered/paid], expected_arrival: date null, published: bool, created_at)`.
  - `Order(id, tender FK, stage, expected_arrival, paid_at)` (or a stage on Tender if round == order).
  - `Supplier(id, name, manufacturer)`, `Outreach(id, tender FK, supplier FK, sent_at, last_reply_at null)`.
  - `Quote(id, tender FK, supplier FK, price, price_unit[carton|sachet], lot_size, sachets_per_carton null, freight_terms[included|to_be_agreed], duties_included bool null, source_channel[web|mcp], created_at)`.
  - `Award(id, tender FK, quote FK, provisional: bool, reason: text, awarded_by FK user, awarded_at)`.
  - `Revision(id, program FK, object_type, object_id, field, old_value, new_value, summary_text, actor_user FK null, actor_kind[human|agent], actor_label e.g. "ACE (agent)", channel[web|mcp], source_excerpt text null, idempotency_key unique null, created_at, rolled_back bool)` — one row per field change, append-only.
- **Write path:** every mutation goes through one `record_change(obj, changes, actor, channel, source_excerpt=None, idempotency_key=None)` service that writes the model and a `Revision`; web views pass `channel="web"`, MCP tools pass `channel="mcp"` + `actor_kind="agent"`.
- **MCP tools** (server-side): `supply_quote_record`, `supply_quote_correct`, `supply_shipment_update`, each accepting `source_excerpt` and `idempotency_key`.
- **Seed command:** `manage.py seed_connect_rutf` (idempotent, `--reset`) creating: org Dimagi; program "Connect-RUTF" with buyer_of_record=Dimagi; user Sophie as member; round 1 tender (quote → award → order → shipment ETA 5 Sep on/before 20 Aug → ETA change to 19 Sep via MCP after 20 Aug → delivered → paid), all with backdated `Revision.created_at`; round 2 tender (opened after 20 Aug) with 3 suppliers' outreach, 2 without reply for ≥14 days, 3 quotes via MCP each blocked by one fact; ≥2 other buyers' programs each with an open published tender. Test: after seed, `Tender.objects.filter(program__name="Connect-RUTF").count() == 2` and re-running seed does not duplicate.
- **Recording mechanics:** walkthrough logs in as Sophie (session fixture), freezes "today" via a `SUPPLY_DEMO_TODAY` setting or seeded dates relative to now; scene 5 requires a between-scene setup hook that calls the `supply_quote_correct` MCP tool (as the ACE agent user) before the scene is captured.

## Scene 1: Sophie reads where her program stands today

- **Route:** `GET /supply/` resolves the user's current program (or `/supply/?program=<slug>`); view `SupplyOverviewView` requiring login + `ProgramMembership`. Test: non-member GET returns 404/403; member GET returns 200.
- **Header:** `<header data-testid="supply-header">` rendering `"{program.name} · {buyer_of_record.name}, buyer of record"`. Test: response contains `"Connect-RUTF · Dimagi, buyer of record"`.
- **Rows:** one `<tr data-testid="overview-row-{tender.id}">` per tender/order scoped to `program=request.program`, columns: stage label (`data-testid="row-stage"`), waiting-on text (`row-waiting-on`, e.g. "waiting on quotes"), last changed (`row-last-changed`: date + actor name from latest `Revision`). Test: only Connect-RUTF tenders appear (other buyers' tender titles absent from response); round 1 row stage text contains "delivered" and "paid".
- **Last-changed derivation:** annotate each tender with its latest Revision (Subquery on `object_id` over tender + child quotes/orders/shipments). Test: after a web edit by Sophie, `row-last-changed` shows "Sophie" and today's date.
- **Stale flag:** `is_stale = any(outreach.last_reply_at is None and outreach.sent_at < today-14d) or any(quote missing basis)` where "missing basis" = `sachets_per_carton is None or freight_terms == to_be_agreed or duties_included is False or lot_size != tender.quantity`; render `<span data-testid="stale-flag">` with reasons ("2 suppliers silent 14+ days", "quotes missing a basis"). Test: round 2 row has stale-flag, round 1 row does not.
- **AI badge:** if latest Revision `channel == "mcp"`, render `<span data-testid="ai-badge">AI</span>`. Test: a row whose last revision is MCP shows the badge; one last edited on web does not.
- **Seed:** round 2 last changed via MCP; round 1 last changed by Sophie (payment recorded on web).

## Scene 2: Sophie finds the day round 1's arrival slipped

- **Route:** `GET /supply/tenders/<id>/` (`TenderDetailView`, member-only). Current-state panel `data-testid="tender-state"` above `<ol data-testid="tender-timeline">`.
- **Timeline query:** Revisions for the tender and its children (quotes, award, order, shipment, payment) ordered `-created_at`; each `<li data-testid="timeline-entry">` renders `summary_text` as one plain sentence (formatter per field, e.g. ETA → `"ETA 5 Sep → 19 Sep"`). Test: first entry is the payment, last is the first quote.
- **Actor rendering:** human → `actor_user.get_full_name()` with no excerpt control; agent → `<button data-testid="actor-badge">ACE (agent)</button>`. Test: Sophie's entries contain her name and no `data-testid="source-excerpt"`.
- **Idempotency / dedupe:** MCP `supply_shipment_update` computes `idempotency_key` = hash(message-id or normalised email body + field + new_value); duplicate key returns the existing Revision without writing. Test: calling the tool twice with the same forwarded email yields exactly one Revision with `new_value="2026-09-19"`, and the timeline has exactly one "ETA 5 Sep → 19 Sep" entry.
- **Excerpt disclosure:** clicking the badge toggles `<blockquote data-testid="source-excerpt">` containing `Revision.source_excerpt` (a `<details>` element, no JS framework needed). Test: the ETA entry's details contain the seeded forwarder excerpt text.
- **Seed:** shipment ETA 5 Sep set by Sophie before 20 Aug; ETA change to 19 Sep submitted twice via the MCP tool with the same email (demonstrates dedupe at seed time).

## Scene 3: Sophie looks at her program as it stood on 20 Aug

- **Control:** header `<input type="date" data-testid="as-of-date" name="as_of">` in a GET form submitting to `/supply/?as_of=2026-08-20`. Test: submitting sets the query param and returns 200.
- **As-of reconstruction:** service `state_as_of(program, date)` — start from current rows, exclude objects with `created_at > date`, and roll back field values by applying Revisions with `created_at > date` in reverse (old_value restored). Test: `state_as_of(rutf, 2026-08-20)` returns round 1 with stage `in_transit` and `expected_arrival == 2026-09-05`, and no round 2.
- **Banner:** when `as_of` present render `<div data-testid="as-of-banner">Viewing as of 20 Aug 2026 — <a data-testid="back-to-today" href="/supply/">back to today</a></div>`. Test: text "Viewing as of 20 Aug 2026" present.
- **Read-only mode:** template flag `read_only=True` hides every write control (all elements with `data-write-control`); POST views reject requests carrying `as_of` (400). Test: as-of response contains zero `data-write-control` elements; normal response contains ≥1.
- **Back to today:** Test: GET `/supply/` after as-of shows round 2 again and no banner.
- **Seed:** backdate round 1's ship Revision to before 20 Aug and ETA change after 20 Aug; round 2 `created_at` after 20 Aug.

## Scene 4: Sophie reads the one thing each round 2 quote is missing

- **Route:** `GET /supply/tenders/<id>/compare/` (`TenderCompareView`).
- **Comparability service:** `classify_quote(quote, tender) -> (comparable: bool, blocker_text, ask_text)`; rules in order: `sachets_per_carton is None` → "Did not say how many sachets a carton holds" / ask "How many sachets does one carton of your RUTF hold?"; `price_unit == sachet and lot_size != tender.quantity` (+ freight to_be_agreed) → "Priced per sachet on a lot of {lot_size}, not the {tender.quantity} asked for; freight still to be agreed" / ask for price on the round's quantity with freight; `duties_included is False` → "Excludes import duties" / ask for a duties-inclusive price. Test: each seeded quote classifies non-comparable with the expected blocker substring.
- **Banner:** `<div data-testid="compare-banner">` reading "None of the 3 quotes can be compared yet" when zero comparable. Test: banner text present.
- **Sections:** `<section data-testid="needs-info">` and `<section data-testid="comparable">`; each quote as `<article data-testid="quote-{id}">` with `blocker` text and `<p data-testid="ask-supplier">Ask the supplier: …</p>`. Test: needs-info has exactly 3 quote articles, each with a non-empty ask-supplier.
- **AI badge:** quote with `source_channel == "mcp"` shows `data-testid="ai-badge"`. Test: all 3 seeded MCP quotes show the badge.
- **Seed:** three quotes, one per blocker, all recorded via MCP tool.
