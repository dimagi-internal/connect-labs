# Cold derivation d6: supply-sophie-rutf

Derived only from the narration payload. Assumes nothing exists unless the text says it does.

## Cross-cutting foundations (used by every scene)

- **Models**
  - `Program(id, name, buyer_of_record_org FK Org)`, `Org(name)`, `ProgramMembership(program FK, user FK)`.
  - `Supplier(org FK, contact_email)`.
  - `Tender(program FK, round_no, product, quantity, unit, delivery_point, deadline, stage enum[open, awaiting_quotes, awarded, ordered, in_transit, delivered, paid], published bool)`.
  - `Order(tender FK, supplier FK, expected_arrival date, status)`, `Payment(order FK, amount, paid_at)`.
  - `Quote(tender FK, supplier FK, unit_price, currency, incoterm, freight enum[included, excluded, not_specified], lead_time_days, status enum[active, corrected, voided], supersedes FK self null)`.
  - `Outreach(tender FK, supplier FK, sent_at, replied_at null)`.
  - `Award(tender FK, quote FK, reason text, provisional bool, awarded_by FK User, awarded_at)`.
- **Revision/provenance table**: `Revision(id, object_type, object_id, program FK, field_changes JSON {field: [old, new]}, summary text, actor_user FK, actor_kind enum[web, mcp_agent], agent_label e.g. "ACE (agent)", source_excerpt text null, idempotency_key char unique null, created_at)`. Every write goes through one `record_change(obj, changes, actor, channel, source_excerpt=None, idempotency_key=None)` service. That service writes the model row and the Revision in the same transaction.
- **Idempotency**: an MCP write whose `idempotency_key` (for example a hash of the source email Message-ID plus the operation) already exists returns the existing Revision and writes nothing new.
- **As-of reconstruction**: `state_as_of(program, date)` starts from the current state and rolls back every Revision created after `date`. An object whose creating Revision falls after `date` is excluded.
- **Permission helper**: `is_program_member(user, program)` gates revisions and excerpts.
- **Seed command** `seed_sophie_rutf`:
  - Program "Connect-RUTF", buyer of record Dimagi, user Sophie as a member.
  - Round 1 with its full history: quote (July), award, order with ETA 5 Sep created before 20 Aug, in transit, ETA change to 19 Sep by ACE after 20 Aug, delivered, paid.
  - Round 2 created after 20 Aug with 3 AI-entered quotes, each missing a basis; one of them has freight `not_specified` although its source excerpt states freight is included.
  - 2 suppliers with outreach older than 14 days and no reply.
  - At least 2 other programs, each with an open published tender.
- **Test fixture**: a pytest fixture `sophie_rutf` runs the seed.

## Scene 1: Sophie reads where her program stands today

- Route: `GET /supply/?program=<id>` (or `/supply/p/<program_id>/`), view `SupplyOverviewView`, login required, 403 if the user is not a program member.
- Header `data-testid="supply-header"` renders `"{program.name} · {buyer_of_record.name}, buyer of record"`, which gives "Connect-RUTF · Dimagi, buyer of record".
- Row list `data-testid="overview-row"` with one row per Tender/Order where `program=this`. Each row has:
  - `data-testid="row-stage"`: stage label, e.g. "delivered, paid" or "open".
  - `row-waiting-on`: "waiting on quotes".
  - `row-last-changed`: "{date} by {actor}", taken from the latest Revision.
  - `row-ai-badge`: shown when the latest Revision has `actor_kind=mcp_agent`.
- Stale logic `stale_reasons(tender)` returns:
  - `unanswered_outreach` when Outreach has `replied_at` null and `sent_at` < now - 14 days;
  - `quote_missing_basis` when any active quote has a null or `not_specified` required basis field (incoterm, freight, currency, lead time).
  - Rendered as `data-testid="stale-flag"` with a title that lists the reasons.
- Test: GET as Sophie returns 200 and contains "Connect-RUTF · Dimagi, buyer of record". It has exactly 2 `overview-row` (round 1 and round 2) and no row from the other programs. The round 2 row contains `stale-flag` naming both reasons. The round 1 row reads delivered/paid. Rows whose last Revision is MCP contain `row-ai-badge`, and a web-last row does not.

## Scene 2: Sophie finds the day round 1's arrival slipped

- Route: `GET /supply/tenders/<id>/`. The detail view shows current state plus `data-testid="timeline"`, built from Revisions on the tender and its quotes/order/payment and ordered `-created_at`.
- Each Revision renders a plain sentence via `summary`. The ETA change renders "ETA 5 Sep → 19 Sep", formatted by the field-change renderer for dates.
- Actor badge `data-testid="actor-badge"`: MCP shows the `agent_label` ("ACE (agent)"); web shows the user's name.
- Excerpt disclosure: clicking the badge (`<details data-testid="source-excerpt">`) reveals `source_excerpt`. Web revisions render no excerpt element.
- MCP write path: an order-update MCP tool accepts `source_excerpt` and `idempotency_key`. A second call with the same key is a no-op.
- Seed: call the ETA update twice with the same email idempotency key.
- Tests:
  - The timeline contains "ETA 5 Sep → 19 Sep" exactly once (`count == 1`).
  - That line's badge text is "ACE (agent)", and its excerpt contains the seeded email text.
  - Lines by Sophie contain "Sophie" and no `source-excerpt`.
  - The first timeline item is the payment and the last is the first quote.
  - A unit test calls `record_change` twice with the same key and asserts `Revision.objects.count()` rose by 1.

## Scene 3: Sophie looks at her program as it stood on 20 Aug

- Overview accepts `?as_of=YYYY-MM-DD`. Header date input `data-testid="as-of-date"` submits via GET.
- When `as_of` is set:
  - Render uses `state_as_of`.
  - Banner `data-testid="as-of-banner"` reads "Viewing as of 20 Aug 2026 — back to today", with the link `data-testid="back-to-today"` pointing to the URL without `as_of`.
  - Every write control (award, correct, new tender buttons) is suppressed.
  - POSTs carrying as_of are rejected with 400.
- Tests:
  - GET `?as_of=2026-08-20` shows the banner text. There is no `data-testid^="write-"` element. The round 1 row reads "in transit" with expected arrival "5 Sep". No round 2 row appears (row count 1).
  - The href of `back-to-today` has no `as_of`.
  - Following it gives 2 rows and no banner.

## Scene 4: Sophie reads what each round 2 quote is missing

- Route: `GET /supply/tenders/<id>/compare/`.
- `compare_quotes(tender)` splits quotes into `comparable` and `needs_info`. For each needs-info quote it returns `missing: [basis]`, with human labels (e.g. "freight terms", "Incoterm", "currency"), and `who_can_answer` (the supplier contact name/org).
- Banner `data-testid="compare-banner"`: "None of the 3 quotes can be compared yet" when `comparable` is empty.
- Section `data-testid="needs-info"` holds rows `data-testid="quote-row"`. Each row has `missing-basis` text, `who-can-answer` text, and `ai-badge` if the quote's creating Revision is MCP.
- Tests: the banner contains "none of the three" / "3". `needs-info` contains 3 `quote-row`, each with a non-empty `missing-basis` in words (no field codes like `incoterm=null`) and a `who-can-answer` naming the supplier. The number of `ai-badge` equals the number of MCP-created quotes (3).

## Scene 5: Sophie checks one AI-entered quote against the email and corrects it

- Route: `GET /supply/quotes/<id>/` shows the quote plus its timeline. The creating Revision sentence reads "Quote recorded … (freight: not specified)" and carries the AI badge and excerpt. Only for members, and only on the latest non-voided version, the line shows the buttons `data-testid="correct-btn"` and `void-btn`.
- Route: `GET/POST /supply/quotes/<id>/correct/`. `QuoteCorrectionForm` has the quote fields plus a required `reason` field.
  - On POST it creates a new Quote with `supersedes=old`, sets the old quote to `status=corrected`, and writes a Revision with `actor_kind=web`, actor Sophie, and summary "Corrected freight: not specified → included — <reason>".
  - It then redirects to the new quote. The new quote's timeline merges its own revisions and the superseded chain's.
- Route: `POST /supply/quotes/<id>/void/` requires a reason and sets `status=voided`.
- Tests:
  - The AI line has `correct-btn` and `void-btn`. Its excerpt contains "freight" and the seeded included wording.
  - A POST to correct with `freight=included, reason="email states CIP incl. freight"` returns 302 to the new quote id. The new quote has freight=included and the old one has status corrected.
  - On the new page, the first timeline item has badge "Sophie" and is above the AI's "Quote recorded" item.
  - A POST without a reason returns a 200 re-render with a form error.

## Scene 6: Sophie sees what other buyers and suppliers can see of round 2

- Route: `GET /supply/market/` lists `Tender.objects.filter(published=True, stage__in=open states)` across all programs, `data-testid="market-row"` showing the buyer org.
- Route: `GET /supply/market/tenders/<id>/` shows only the fields product, quantity, delivery_point and deadline (`data-testid="published-fields"`). The template has no timeline, excerpt or quote blocks. The view serializer uses an allow-list of fields.
- The member-only tender detail returns 403/404 to non-members. The member view keeps revisions/excerpts.
- Seed: a non-member user "other_supplier".
- Tests:
  - The market list contains Sophie's round 2 plus ≥2 rows with a different buyer.
  - The market detail for round 2 contains product/quantity/delivery point/deadline. It has no `timeline`, no `source-excerpt`, no `quote-row`, and no supplier price string.
  - As other_supplier, `GET /supply/tenders/<round2>/` returns 403 or 404.

## Scene 7: Sophie awards round 2 and says why she will not wait

- Update `compare_quotes`: after the correction, the corrected quote is `comparable` and ranked (rank 1). It is marked `provisional=True` when any other active quote is still in `needs_info`. The label is `data-testid="provisional-flag"`.
- Each ranked row gets an award form: `reason` textarea `data-testid="award-reason"` (required when provisional) and button `data-testid="award-btn"`. The form posts to `POST /supply/tenders/<id>/award/` with `quote_id`.
- The server creates `Award(provisional=<computed>, reason, awarded_by=request.user)`, sets tender stage to awarded, writes a web Revision, and redirects to the overview.
- Overview row stage renders "awarded, provisional" and last-changed "today by Sophie".
- Tests:
  - Before the award, the comparison shows the corrected quote ranked with `provisional-flag`, and the other 2 quotes are still in needs-info.
  - A POST award with a reason returns 302 to the overview. The Award has `provisional=True` and reason saved.
  - The overview round 2 row contains "awarded", "provisional", today's date and "Sophie", and no `row-ai-badge`.
  - A POST without a reason while provisional is rejected.
