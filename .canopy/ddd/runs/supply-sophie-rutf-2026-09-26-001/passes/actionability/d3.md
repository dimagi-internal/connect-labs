# Actionability derivation d3 (cold, from narration only)

Shared foundations the scenes imply (built once, referenced below):
- `Program(id, name="Connect-RUTF", buyer_of_record=FK Org "Dimagi")`.
- `Tender(id, program FK, round_no, title, commodity, quantity, unit, delivery_point, deadline, stage ∈ {open, awaiting_quotes, awarded, ordered, in_transit, delivered, paid}, expected_arrival date, published bool)`.
- `Order/Shipment(id, tender FK, eta date, status)`, `Payment(id, order FK, paid_at)`.
- `Quote(id, tender FK, supplier Org FK, unit_price, currency, freight_terms ∈ {included, excluded, not_specified}, incoterm, pack_size, lead_time_days, superseded_by FK self null, version int)`.
- `Outreach(id, tender FK, supplier FK, sent_at, replied_at null)`.
- `ChangeEvent` (append-only history): `id, entity_type, entity_id, program FK, field, old_value JSON, new_value JSON, summary text, actor_user FK null, actor_kind ∈ {human, agent}, actor_label ("Sophie", "ACE (agent)"), channel ∈ {web, mcp}, source_excerpt text null, source_ref (e.g. email message-id) null, reason text null, occurred_at`.
- Every write goes through one `record_change(entity, field, new, actor, channel, source_excerpt=None, reason=None)` choke point, so history/provenance cannot be bypassed.
- Seed command `manage.py seed_sophie_rutf` (idempotent) building the fixture used by every scene, with a frozen "today" of 2026-09-26.

## Scene 1: Sophie reads where her program stands today

- Route `GET /supply/?program=<id>` (or `/supply/programs/<id>/`) → view `program_overview`, template `supply/overview.html`.
- Header element `data-testid="supply-header"` rendering `"{program.name} · {buyer_of_record.name}, buyer of record"`.
  - Test: `assert "Connect-RUTF · Dimagi, buyer of record" in resp.content.decode()`.
- Query: tenders + orders filtered `program=<id>` only; one `<tr data-testid="overview-row" data-tender-id=…>` per tender/order.
  - Test: seed a second program with a tender "Other-R1"; `assert "Other-R1" not in body` and row count == 2.
- Each row columns: `stage` (`data-testid="row-stage"`), `waiting_on` (`data-testid="row-waiting-on"`, derived: awaiting_quotes → "quotes from N suppliers"), `last_changed` (`data-testid="row-last-changed"`, "<date> by <actor_label>") from the latest `ChangeEvent` for the tender or any child entity.
  - Test: round 1 row stage text contains "delivered" and "paid"; round 2 contains "open" and "waiting on quotes".
- Stale flag service `staleness(tender, today)`: flags (a) `Outreach` with `replied_at is None and sent_at <= today-14d`, (b) any live `Quote` with a required basis field null/`not_specified`. Render `<span data-testid="stale-flag">` with reasons listed.
  - Test: round 2 row has `stale-flag` naming the silent supplier(s) and "quote missing basis"; round 1 row has none.
- AI badge: `<span data-testid="ai-badge">AI</span>` when latest ChangeEvent for the row has `channel="mcp"`.
  - Test: set round 2's latest event channel=mcp → badge present; round 1 (latest by Sophie, web) → absent.
- Seed: program Connect-RUTF, Dimagi org, round 1 (delivered + paid, events from quote to payment), round 2 (open, 3 outreach rows, one unanswered since 2026-09-08), 3 quotes entered via MCP, at least one with freight not_specified.

## Scene 2: Sophie finds the day round 1's arrival slipped

  - Test: first item mentions payment, last item is the first quote recorded (`items[0]` contains "paid", `items[-1]` contains "Quote recorded").
- Summary formatter `describe_change(event)` for date fields: `f"ETA {old:%-d %b} → {new:%-d %b}"`.
  - Test: `assert describe_change(evt) == "ETA 5 Sep → 19 Sep"`.
- Badge click opens a disclosure (`<details data-testid="source-excerpt">`) showing `source_excerpt` and `source_ref`; no JS required.
  - Test: the ETA item contains badge text "ACE (agent)" and a `source-excerpt` whose text equals the seeded forwarder email excerpt.
- Seed: round 1 shipment ETA event on e.g. 2026-08-28, old 2026-09-05, new 2026-09-19, actor_kind=agent, actor_label "ACE (agent)", channel=mcp, source_excerpt = a forwarder email quote (synthetic, no PII).
- MCP write path must require `source_excerpt` for agent writes (refuse otherwise).
  - Test: calling the MCP shipment-update op without `source_excerpt` raises a validation error.

## Scene 3: Sophie looks at her program as it stood on 20 Aug

- Header date control `<input type="date" name="as_of" data-testid="as-of-date">` inside a GET form; submits `/supply/?program=<id>&as_of=2026-08-20`.
- As-of reconstruction: `state_as_of(entity, ts)` = current state rolled back by undoing every `ChangeEvent` with `occurred_at > ts` (replay old_value), and entities whose creation event is after `ts` are excluded.
  - Test: `state_as_of(round1, 2026-08-20).stage == "in_transit"` and `.expected_arrival == date(2026,9,5)`.
  - Test: round 2 (created 2026-09-01 in seed) absent: `"Round 2" not in body` for the as_of request.
- Banner `data-testid="as-of-banner"`: "Viewing as of 20 Aug 2026 — back to today", with `<a data-testid="back-to-today" href="/supply/?program=<id>">`.
  - Test: banner text exact match; back link href has no `as_of`.
- Read-only mode: context flag `read_only=True` hides all write controls (award/correct/new buttons, `data-testid^="action-"`) and write views reject `as_of` requests with 403/redirect.
  - Test: `assert 'data-testid="action-' not in body` for as_of response; POST with as_of → 403.
- Seed: round 1 events dated so that on 20 Aug it was in_transit with ETA 5 Sep (ETA change dated after 20 Aug), round 2 created after 20 Aug.

## Scene 4: Sophie reads what each round 2 quote is missing

- Grouping: quotes with any missing basis → "Needs info" section `data-testid="needs-info"`; others → ranked table `data-testid="ranked"`.
- Banner `data-testid="compare-banner"`: when ranked empty, "None of the 3 quotes can be compared yet".
  - Test: `assert "None of the 3 quotes can be compared yet" in body`.
- Each needs-info row `data-testid="needs-info-row"` shows words like "Missing: freight terms — ask <Supplier>".
  - Test: 3 rows; each has non-empty missing text and supplier name.
- AI badge on rows whose creating ChangeEvent channel=mcp.
  - Test: number of `ai-badge` in needs-info == seeded MCP-entered quote count.
- Seed: 3 round 2 quotes from 3 suppliers, each missing a different basis (freight not_specified; incoterm null; pack size null).

## Scene 5: Sophie checks one AI-entered quote against the email and corrects it

- Route `GET /supply/quotes/<id>/` → quote detail with timeline (reuse timeline component) and "Correct" button `data-testid="action-correct"`.
- Timeline item "Quote recorded … (freight: not specified)" with actor badge (AI) and source excerpt disclosure containing supplier email that states freight terms.
  - Test: excerpt text contains "freight" and "included" (seeded wording) while quote.freight_terms == "not_specified".
- Route `GET/POST /supply/quotes/<id>/correct/` → `QuoteCorrectionForm(ModelForm fields: freight_terms, incoterm, unit_price, …; plus required reason textarea)`.
- Server: correction creates new Quote version (`version+1`, original.superseded_by=new), copies ChangeEvent history link (new quote's timeline includes predecessor events), writes `ChangeEvent(field="freight_terms", old="not_specified", new="included", actor=Sophie, actor_kind=human, channel=web, reason=<text>)`; redirect to new quote detail.
  - Test: POST → 302 to `/supply/quotes/<new_id>/`; `Quote.objects.get(pk=old).superseded_by_id == new_id`; new `.freight_terms == "included"`.
  - Test: POST without reason → form error "reason required", no new version.
  - Test: new quote timeline first item badge "Sophie" and contains reason; a later item is the AI's original "Quote recorded" entry.
- Comparison and overview use only non-superseded quotes.
  - Test: compare page lists 3 quotes, not 4.
