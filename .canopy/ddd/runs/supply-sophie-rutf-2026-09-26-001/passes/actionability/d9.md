# Actionability cold derivation — d9 (supply-sophie-rutf)

Derived only from the scene narration/show/claim text. Nothing is assumed to exist.

## Scene 1: Sophie reads where her program stands today

- **Data model.** `Program(id, name="Connect-RUTF", buyer_of_record=FK Org("Dimagi"))`. `Tender(id, program FK, round_number, title, stage ∈ {draft, open, awaiting_quotes, awarded, ordered, in_transit, delivered, paid}, waiting_on text, updated_at, updated_by FK User null, updated_via ∈ {web, mcp})`. `Order(id, tender FK, stage, expected_arrival date, updated_at, updated_by, updated_via)`. `Outreach(id, tender FK, supplier FK Org, sent_at, last_reply_at null)`. `Quote(id, tender FK, supplier FK, price, price_basis nullable, units_per_carton nullable, lot_size, freight_terms, duties_included bool, updated_via)`.
  - Test: `Tender.objects.create(... updated_via="mcp")` round-trips, and `Program.buyer_of_record.name == "Dimagi"`.
- **Provenance stamping.** Every write goes through one `record_change(obj, actor, via, source_excerpt=None)` helper. It sets `updated_at`, `updated_by` and `updated_via` (`web` from views, `mcp` from MCP tools) and writes a revision row (see Scene 2).
  - Test: an MCP tool call that updates a tender gives `tender.updated_via == "mcp"` and `updated_by == agent_user`.
- **Staleness service.** `stale_reasons(tender, today)` returns `["no_reply_14d:<supplier>", "quote_missing_basis:<supplier>"]` when an Outreach has `last_reply_at is None and sent_at <= today-14d`, or when a Quote has `price_basis is None`.
  - Test: an outreach sent 15 days ago with no reply gives a `no_reply_14d` entry. One sent 13 days ago gives none.
- **Endpoint.** `GET /supply/?program=<id>` (or `/supply/p/<program_id>/`), view `supply_overview`. It filters tenders and orders to `program_id` only, and the user must be a program member.
  - Test: a tender that belongs to another program is not in `response.context["rows"]`.
- **UI.** Header `data-testid="supply-header"` with the text "Connect-RUTF · Dimagi, buyer of record". One `data-testid="overview-row-<tender_id>"` per tender or order, containing:
  - `row-stage`
  - `row-waiting-on`
  - `row-last-changed` ("<date> by <name>")
  - `row-stale-flag` (with a tooltip listing reasons)
  - `ai-badge`, only when `updated_via == "mcp"`
  - Test: the response contains "Dimagi, buyer of record". The round 2 row contains `data-testid="row-stale-flag"`. The round 1 row does not.
- **Seed.** Command `seed_sophie_rutf`:
  - Program Connect-RUTF with buyer Dimagi. Sophie is a member.
  - Round 1: tender awarded and an order delivered and paid, written by Sophie on the web.
  - Round 2: open, awaiting quotes. There are 3 outreaches. Two were sent at least 14 days ago with no reply. Three quotes arrived via MCP, one with `price_basis=None`.
  - An agent user named "ACE (agent)".
  - Test: after running the seed, the overview shows 2 rows and the round 2 row has the AI badge.
- **Recording.** Log in as Sophie, navigate to `/supply/?program=<id>`, pause on the header and each row. Target selectors are the testids above.

## Scene 2: Sophie finds the day round 1's arrival slipped

- **Data model.** `Revision(id, content_type, object_id, tender FK (denormalised for the timeline), field, old_value, new_value, summary text, actor FK User, via ∈ {web, mcp}, source_excerpt text null, idempotency_key char unique null, created_at)`. There is one row per field change.
  - Test: changing `order.expected_arrival` from 2026-09-05 to 2026-09-19 creates a Revision with `summary == "ETA 5 Sep → 19 Sep"`.
- **Idempotency.** The MCP write tools, such as `supply_chain_shipment_update`, accept `idempotency_key` (for example a hash of the source email Message-ID). A repeat call with the same key returns the original result and writes nothing.
  - Test: calling the tool twice with the same key and excerpt leaves `Revision.objects.filter(summary__startswith="ETA").count() == 1`.
- **Sentence renderer.** `render_revision(rev)` produces plain sentences such as "Quote received from X", "ETA 5 Sep → 19 Sep" and "Payment recorded".
  - Test: the renderer output for each seeded revision contains no field or database names.
- **Endpoint.** `GET /supply/tenders/<id>/` shows the current state panel followed by the timeline, ordered by `-created_at`. It is limited to program members.
  - Test: the first timeline item is the payment revision and the last is the first quote.
- **UI.** `data-testid="tender-current-state"`, `data-testid="timeline"` and `data-testid="timeline-item-<rev_id>"`.
  - MCP items get `data-testid="actor-badge"` with the text "ACE (agent)". It is a `<button>` that toggles `data-testid="source-excerpt"` (a `<details>` element, with no Bootstrap).
  - Web items show `actor-name` = "Sophie …" and have no `source-excerpt` element.
  - Test: the response has exactly one element containing "ETA 5 Sep → 19 Sep". Its item contains `source-excerpt` with the seeded email text. Sophie's items contain her name and no `source-excerpt`.
- **Seed.**
  - Round 1 history from the first quote through award, dispatch and ETA change to payment, with realistic `created_at` dates.
  - The ETA change is written via the MCP tool twice, with the same idempotency key and the forwarder's excerpt.
  - The other entries are written as Sophie via the web path.
- **Recording.** Open the round 1 page, scroll to `text:ETA 5 Sep → 19 Sep`, click its `actor-badge`, and hold on the excerpt.

## Scene 3: Sophie looks at her program as it stood on 20 Aug

- **Server behaviour.** An `?as_of=YYYY-MM-DD` param on the overview view reconstructs state at the end of that date:
  - Tenders and orders whose `created_at > as_of` are excluded.
  - Each field value is rewound by applying Revisions newer than `as_of` in reverse (`old_value`).
  - The result is served read-only, with no mutation.
  - Test: `?as_of=2026-08-20` gives a round 1 row with stage `in_transit` and `expected_arrival == 2026-09-05`, and no round 2 row.
- **Read-only enforcement.** When `as_of` is set:
  - The context has `read_only=True`, and templates hide every `data-testid^="write-"` control.
  - POST requests with `as_of` are rejected with 400/403.
  - Test: with `as_of`, the response HTML has no `data-testid="write-` string.
- **UI.**
  - Header date input `data-testid="as-of-date"` (type=date). Changing it submits a GET with `as_of`.
  - Banner `data-testid="as-of-banner"` with the text "Viewing as of 20 Aug 2026 — back to today". The link `data-testid="back-to-today"` points to the overview URL without `as_of`.
  - Test: the banner text matches, and the `back-to-today` href has no `as_of`.
- **Seed.**
  - Round 1: on or before 20 Aug it is in transit with ETA 5 Sep. The ETA change is dated after 20 Aug.
  - Round 2 tender: `created_at` after 20 Aug.
  - Delivered/paid revisions: after 20 Aug.
  - Test: the seed dates satisfy these assertions (the `as_of` test above).
- **Recording.** Fill `css:[data-testid=as-of-date]` with 2026-08-20 and submit. Wait for `as-of-banner`. Click `back-to-today`, then wait until the banner is absent.

## Scene 4: Sophie reads the one thing each round 2 quote is missing

- **Comparability service.** `classify_quote(quote, tender)` returns `(status ∈ {comparable, needs_info}, blocker_text, ask_text)`. It checks the rules below in order and reports the first failing one:
  - `units_per_carton is None` gives "Sachets per carton not stated".
  - `price_basis == "per_sachet" and lot_size != tender.quantity` gives "Priced per sachet on a larger lot than the round asked for; freight still to be agreed". The freight part comes from `freight_terms == "tba"`.
  - `duties_included is False` gives "Import duties excluded".
  - Each rule has a templated question, for example "How many sachets does one carton hold?"
  - Test: each of the three seeded quotes maps to its expected blocker text, and all three return `needs_info`.
- **Endpoint.** `GET /supply/tenders/<id>/compare/`, limited to program members.
  - Test: `context["comparable"] == []` and `len(context["needs_info"]) == 3`.
- **UI.**
  - Banner `data-testid="compare-banner"` with the text "None of the 3 quotes can be compared yet".
  - Section `data-testid="needs-info"` with one `data-testid="quote-row-<id>"` per quote, each containing `quote-blocker`, an `ask-supplier` block with the heading "Ask the supplier" and the question text, and `ai-badge` when the quote's `updated_via == "mcp"`.
  - Test: the response contains the three blocker strings and three "Ask the supplier" blocks.
- **Seed.** Three suppliers' quotes arrive via MCP:
  - Supplier A: `units_per_carton=None`.
  - Supplier B: per-sachet price, larger lot, freight tba.
  - Supplier C: `duties_included=False`.
  - Test: seeding then running `classify_quote` gives no comparable quotes.
- **Recording.** Open the compare URL and hold on each `quote-row`.

## Scene 5: A supplier answers, and the quote joins the ranking

- **MCP tool.** `supply_chain_quote_correct(quote_id, fields={"units_per_carton":150}, source_excerpt, idempotency_key)`. It goes through `record_change` with `via=mcp` and writes a Revision with the summary "Quote from <A> corrected to 150 sachets per carton".
  - Test: after the call, `quote.units_per_carton == 150` and the newest round 2 Revision is via mcp with the excerpt set.
- **Landed cost.** `landed_cost(quote)` returns `per_carton = (unit_price*units_per_carton or carton price) + freight_per_carton + duties_per_carton`. It also returns `per_child = per_carton / cartons_per_child`, where `cartons_per_child` is a tender or commodity setting (for example a 150-sachet carton is one child's course, so `per_child = per_carton * cartons_per_treatment`). Comparable quotes are ranked ascending by `per_carton`.
  - Test: for the seeded supplier A figures, the function returns the expected `Decimal` values.
- **UI (compare).** Section `data-testid="comparable"` with rows `quote-row-<id>` showing `rank`, `landed-cost-per-carton` and `cost-per-child`. B and C remain in `needs-info`.
  - Test: after the correction, `context["comparable"]` holds A with rank 1 and `needs_info` holds B and C.
- **UI (timeline).** The top item of `/supply/tenders/<r2>/` is the correction, with the "ACE (agent)" badge and an excerpt containing "150".
  - Test: the first `timeline-item` contains "150 sachets per carton" and "ACE (agent)".
- **Demo mechanics.** A pre-recording step calls the MCP tool (or a management command `supply_demo_step --reply-a`) as the agent user with the reply excerpt. It is idempotent so re-recordings don't duplicate.
  - Test: running the step twice gives a single correction revision.
- **Recording.** Run the setup step, open round 2, click the top badge, then navigate to compare and hold on `comparable`.
