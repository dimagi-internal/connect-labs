# Cold derivation d8 — supply-sophie-rutf

Derived only from the narration payload. Nothing is assumed to exist beyond what the text states.

## Cross-cutting foundations (needed by several scenes)

- **Program model**: `Program(id, name="Connect-RUTF", buyer_of_record_org FK -> Org("Dimagi"))`, with `ProgramMembership(program, user, role)`. Test: `Program.objects.get(name="Connect-RUTF").buyer_of_record_org.name == "Dimagi"`.
- **Tender model**: `Tender(program FK, round_number, title, product, quantity, delivery_point, deadline, status ∈ {open, awarded, in_transit, delivered, paid}, expected_arrival date, is_published bool)`. Test: after seeding, `Tender.objects.filter(program=rutf).count() == 2`.
- **Quote model**: `Quote(tender FK, supplier FK Org, unit ∈ {carton, sachet}, price, lot_size, sachets_per_carton nullable int, freight_terms nullable, duties_included nullable bool, currency, source_channel ∈ {web, mcp})`. Test: a quote with `sachets_per_carton=None` exists on round 2.
- **Revision/history table** `RecordRevision(id, record_type, record_id, program FK, field, old_value, new_value, sentence text, actor_user FK, actor_kind ∈ {human, agent}, actor_label e.g. "ACE (agent)", channel ∈ {web, mcp}, source_excerpt text nullable, idempotency_key unique nullable, occurred_at, rolled_back bool)`. Every write (web form or MCP tool) goes through one `record_change()` service that writes the row and the revision atomically. Test: `record_change(...)` on a quote creates exactly one `RecordRevision` with matching `record_id`.
- **Idempotency**: MCP write tools accept `idempotency_key` (e.g. hash of source email Message-ID + field); a second call with the same key returns the first result and writes no new revision. Test: calling the ETA update twice with the same key leaves `RecordRevision.objects.filter(field="expected_arrival").count() == 1`.
- **Outreach model**: `Outreach(tender FK, supplier FK, sent_at, replied_at nullable)` to drive the "silent two weeks" stale flag.
- **AI badge rule**: a row is AI-badged when its latest `RecordRevision.channel == "mcp"`. Template partial `_ai_badge.html` renders `<span data-testid="ai-badge">AI</span>`.
- **Seed command** `manage.py seed_sophie_rutf --reset`: creates Dimagi org, Sophie user (program member), ACE agent user, three suppliers, round 1 (quote → award → shipment ETA 5 Sep recorded before 20 Aug → ETA changed to 19 Sep via MCP with excerpt, submitted twice with the same idempotency key → delivered → paid), round 2 (opened after 20 Aug, three quotes via MCP each with one blocker, outreach to two suppliers sent > 14 days ago with no reply), plus two other programs/buyers with open published tenders. All timestamps fixed relative to a pinned "today" (26 Sep 2026). Test: running the seed twice yields identical counts (idempotent).
- **Demo recording**: a scene-5 "supplier reply" step is scripted as a setup call to the MCP tool `quote_correct` with the reply excerpt (not typed on camera); recorder uses Sophie's stored session; every assertion target has a `data-testid`.

## Scene 1: Sophie reads where her program stands today

- **Route** `GET /supply/?program=<id>` (or `/supply/p/<program_slug>/`) → `SupplyOverviewView`, requires `ProgramMembership`. Test: non-member gets 404/403; Sophie gets 200.
- **Header**: `<h1 data-testid="supply-header">` rendering `"{program.name} · {buyer_of_record.name}, buyer of record"`. Test: response contains `"Connect-RUTF · Dimagi, buyer of record"`.
- **Scoping**: queryset `Tender.objects.filter(program=program)` plus orders; no other program's rows. Test: seeded other-buyer tender title is absent from the response.
- **Row per tender/order** `data-testid="overview-row-<tender_id>"` with columns: stage (`data-testid="row-stage"`), waiting-on (`row-waiting-on`, derived: open tender with quotes blocked → "waiting on quotes"), last changed (`row-last-changed` = latest revision `occurred_at` humanised + actor display name). Test: round 1 row stage text contains "delivered" and "paid"; round 2 row contains "open" and "waiting on quotes".
- **Stale flag** computed server-side: `stale_reasons = [outreach with sent_at < now-14d and replied_at is null] + [quotes where missing-basis check fails]`; render `<span data-testid="stale-flag" title="...">`. Test: round 2 row has `stale-flag`; round 1 row does not; tooltip lists the two silent suppliers.
- **AI badge** on rows whose last revision `channel="mcp"`. Test: round 2 row contains `data-testid="ai-badge"`; a row last edited on web does not.
- **Test (view-level)**: pytest client GET as Sophie, assert exactly 2 `overview-row-` elements for Connect-RUTF.

## Scene 2: Sophie finds the day round 1's arrival slipped

- **Timeline query**: all `RecordRevision` for the tender and its children (quotes, award, shipment, invoice, payment), ordered `-occurred_at`; each rendered as `<li data-testid="timeline-line">{sentence}</li>`. Test: first line refers to payment, last line to the first quote.
- **Plain sentences**: `sentence` generated per field type, e.g. dates as `"ETA 5 Sep → 19 Sep"`. Test: exactly one line whose text contains `"ETA 5 Sep → 19 Sep"`.
- **Actor labels**: human web lines show `actor_user.get_full_name()` and no excerpt control; agent lines show a badge `<button data-testid="actor-badge-agent">ACE (agent)</button>`. Test: lines with `channel="web"` contain "Sophie" and no `source-excerpt` element.
- **Dedup of double-forwarded email**: enforced by idempotency key (see foundations). Test: seed submits the ETA change twice; timeline has one ETA line.
- **Excerpt reveal**: clicking the badge toggles `<blockquote data-testid="source-excerpt">` (use `<details>` / Alpine, no Bootstrap) containing `source_excerpt`. Test: HTML for the ETA line contains the seeded forwarder email excerpt inside `source-excerpt`.
- **MCP tool** `supply_chain_shipment_update(shipment_id, expected_arrival, source_excerpt, idempotency_key)` writing through `record_change` with `channel="mcp"`, actor = token's user flagged `is_agent`. Test: tool call produces a revision with `actor_label == "ACE (agent)"`.
