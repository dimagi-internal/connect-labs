# Actionability cold derivation — d2

Derived only from the narration payload. Shared foundations (used by several scenes) are listed once under Scene 1 and referenced after that.

## Scene 1: Sophie reads where her program stands today

- **Data model: Program + buyer of record.** `SupplyProgram(id, name="Connect-RUTF", slug, buyer_org FK -> Org)`; `Org(name="Dimagi")`. The overview must be filtered to one program.
  - Test: `assert program.buyer_org.name == "Dimagi"` and GET `/supply/?program=<id>` → `"Connect-RUTF · Dimagi, buyer of record" in response.text`.
- **Data model: Tender (a "round") and Order.** `Tender(id, program FK, title="Round 1"/"Round 2", stage enum[open, awaiting_quotes, awarded, in_transit, delivered, paid], opened_at, deadline, commodity, quantity, delivery_point, published bool)`; `Order(id, tender FK, supplier FK, eta date, stage)`.
  - Test: create Tender for another program; assert its title does not appear on Connect-RUTF's overview (scoping).
- **Data model: change log / record history.** `RecordEvent(id, content_type, object_id, program FK, at datetime, actor FK User, actor_kind enum[human, agent], via enum[web, mcp], summary text, field, old_value, new_value, source_excerpt text null, source_ref text null, supersedes FK self null)`. Every write path (web form + MCP tool) appends one row in the same transaction.
  - Test: call the tender-update operation via the MCP entrypoint → `RecordEvent.objects.filter(object_id=t.id).latest("at").via == "mcp"`.
- **Data model: outreach + quote basis.** `Outreach(tender FK, supplier FK, sent_at, replied_at null)`; `Quote(tender FK, supplier FK, unit_price, currency, incoterm/freight enum[included, excluded, not_specified], lead_time_days null, validity null, basis_missing computed list)`.
- **Server: overview view** `GET /supply/` (program from `labs_context` / `?program=`). Builds one row per tender/order with: stage label, "waiting on" text (e.g. "waiting on quotes"), `last_changed_at` and `last_changed_by` from latest `RecordEvent`, `stale` = any Outreach with `replied_at IS NULL and sent_at < now-14d` OR any quote with non-empty `basis_missing`, `ai_badge` = latest event `via == "mcp"`.
  - Test: with Outreach sent 15 days ago and no reply, row for round 2 has `data-testid="stale-flag"`; with sent 13 days ago, it does not.
- **UI** (template `supply/overview.html`): header `data-testid="supply-program-header"`; rows `data-testid="tender-row-<id>"` containing `data-testid="row-stage"`, `row-waiting-on`, `row-last-changed` ("<date> by <name>"), `stale-flag` (with tooltip listing the unanswered suppliers and quotes missing a basis), `ai-badge` (label "AI").
  - Test: round 1 row text contains "Delivered" and "Paid"; round 2 row contains "Waiting on quotes" and has both `stale-flag` and `ai-badge`.
- **Seed** (idempotent management command `seed_sophie_rutf`): program Connect-RUTF, Dimagi buyer, user Sophie (member), agent user "ACE" (`actor_kind=agent`); Round 1 with full history quote → award → order → shipment ETA 5 Sep → ETA 19 Sep (ACE, mcp, with forwarder excerpt) → delivered → paid; Round 2 open 2026-09-01, three supplier outreach rows (two unreplied > 14 days), three quotes entered via MCP each missing at least one basis (one with freight=not_specified); at least two other programs/buyers with open published tenders.
  - Test: running the seed twice leaves `Tender.objects.filter(program=p).count() == 2`.

## Scene 2: Sophie finds the day round 1's arrival slipped

- **Route:** `GET /supply/tenders/<id>/` tender detail with "current state" block (`data-testid="tender-current-state"`) and timeline (`data-testid="timeline"`) listing RecordEvents for the tender and all descendants (quotes, award, order, shipment, payment) ordered `-at`.
  - Test: first `timeline-entry` is the payment event; last is the first quote event.
- **Plain-sentence rendering:** `RecordEvent.sentence()` renders e.g. `"ETA 5 Sep → 19 Sep"` for field changes (`"<Label> <old> → <new>"`, dates as `%-d %b`), `"Quote recorded …"` for creates.
  - Test: `event.sentence() == "ETA 5 Sep → 19 Sep"` for a shipment eta change 2026-09-05 → 2026-09-19.
- **Actor badge:** each entry has `data-testid="actor-badge"`; label `"ACE (agent)"` when `actor_kind=agent`, else user display name.
  - Test: the ETA entry's badge text == "ACE (agent)".
- **Source excerpt reveal:** clicking the badge opens a disclosure/popover (`<details data-testid="source-excerpt">`) showing `source_excerpt` and `source_ref` (e.g. "Email from forwarder, 3 Sep"). Server: MCP write tools accept a required-for-agents `source_excerpt` argument, stored on the event.
  - Test: GET tender page → ETA entry contains the seeded forwarder excerpt text inside `source-excerpt`; MCP write by an agent without `source_excerpt` is refused (400/ValueError).
- **Seed:** forwarder excerpt text on the ETA event.

## Scene 3: Sophie looks at her program as it stood on 20 Aug

- **UI control:** header date input `data-testid="as-of-date"` (type=date) submitting `GET /supply/?as_of=2026-08-20`.
- **Server: as-of reconstruction.** For `as_of`, include only tenders/orders whose creating event `at <= as_of`; reconstruct field values by rolling back events with `at > as_of` (apply `old_value` in reverse order). Stage, ETA, last-changed come from the rewound state.
  - Test: `/supply/?as_of=2026-08-20` → round 1 row stage "In transit", expected arrival "5 Sep"; `"Round 2" not in response.text`.
- **Banner:** `data-testid="as-of-banner"` text "Viewing as of 20 Aug 2026 — back to today", with link `data-testid="back-to-today"` href `/supply/` (no as_of).
  - Test: banner text matches; following link returns page without the banner and with Round 2.
- **Read-only mode:** when `as_of` set, template omits all write controls (Correct, Award, New tender buttons: `data-testid^="action-"`); POST endpoints reject requests carrying `as_of` (403).
  - Test: `'data-testid="action-' not in as_of_response.text`.
- **Seed:** round 1 shipment events dated such that on 20 Aug stage=in_transit and eta=5 Sep; round 2 created after 20 Aug (e.g. 1 Sep).

## Scene 4: Sophie reads what each round 2 quote is missing

- **Route:** `GET /supply/tenders/<id>/compare/`.
- **Server: comparability.** A quote is comparable only if basis fields (freight/Incoterm, currency, unit, lead time, validity) are all specified; otherwise grouped under "Needs info". Each missing basis maps to a sentence ("Freight terms not stated — ask <Supplier contact>") and an "who can answer" (supplier contact name/email from `Supplier.contact`).
  - Test: `compare(tender).needs_info` has 3 quotes, `compare(tender).ranked == []`.
- **UI:** banner `data-testid="compare-banner"` "None of the 3 quotes can be compared yet"; section `data-testid="needs-info"` with `quote-row-<id>` each containing `missing-basis` (words, not codes) and `who-can-answer`, plus `ai-badge` when the quote's creating event `via=mcp`.
  - Test: each of three rows has non-empty `missing-basis` text not containing `_` (no raw field keys); `ai-badge` present on the MCP-entered quotes.
- **Seed:** three round 2 quotes each missing a different basis, with supplier contacts.

## Scene 5: Sophie checks one AI-entered quote against the email and corrects it

- **Route:** `GET /supply/quotes/<id>/` quote detail with its own timeline (reuse timeline partial). Create event sentence: `"Quote recorded … (freight: not specified)"`, AI badge, source excerpt of the supplier email that actually states freight included.
  - Test: the quote page's first-created entry contains "(freight: not specified)" and its `source-excerpt` contains "freight" wording from seed.
- **Correct action:** button `data-testid="action-correct"` → `GET/POST /supply/quotes/<id>/correct/` ModelForm with quote fields + required `reason` textarea (`name="reason"`). POST goes through the domain operation `quote_correct` which creates a new Quote version (`supersedes` FK to old, old marked `superseded`) and a RecordEvent (actor=Sophie, via=web, summary incl. reason), then redirects to the new version.
  - Test: POST `{freight: "included", reason: "Email says freight included"}` → 302 to `/supply/quotes/<new_id>/`; `Quote.objects.get(id=new_id).freight == "included"`; old quote `.superseded_by_id == new_id`; POST without reason → form error.
- **Timeline continuity:** new version's timeline includes the predecessor chain's events; correction entry badged "Sophie" appears above the AI's original entry.
  - Test: entries order: [correction(actor "Sophie"), original(actor "ACE (agent)")].
- **Seed:** supplier email excerpt stating freight included on the quote whose freight was recorded not_specified.
