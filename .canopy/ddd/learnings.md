## nutrition-demo 2026-07-23 (photo rail + AI census; 3 re-records)
- REQUEST-FIDELITY, not concept-fidelity, was the miss that cost a whole render cycle. The v1 per-child view shipped a TEXT visit list when the request (thread msg 8) was explicitly "photographs for each visit on the left rail ... one image per visit that you can expand". No DDD judge catches this class: concept/visual judges score a scene against the spec's own `concept_claim`, and the spec faithfully described the list it built. Only `agent-turn-review` §A (re-read the ORIGINAL request) catches spec-vs-request drift — and it runs at send time, i.e. one render too late. If a narrative is built to satisfy a written request, diff the spec against that request BEFORE the first render.
- `must_succeed: false` turns a broken action into a GREEN run report. The closing scene dismissed the photo overlay via `click css:.fixed.inset-0`; Playwright clicks an element's CENTRE, which is the inner card whose onClick calls stopPropagation — so the click hit the photo and the overlay never closed, covering the payoff chart for the scene's tail. The recorder still printed "70 actions: all ok". Any action whose failure would change what a viewer sees must be `must_succeed: true`. Backdrop-dismiss is never a reliable recorder target — give the component a real close control and target that.
- A modal with click-outside as its ONLY dismissal is a product defect the walkthrough surfaces first. Added a close button + Escape handler; the recorder's need for a deterministic target and the user's need for an obvious exit are the same requirement.
- `ddd-ace-render` does NOT judge. It records → emits spec → renders → uploads. Two cuts shipped unjudged before the human caught the overlay in seconds. Run `ddd-timing-eval` (free, auto-written to the run dir as verdict-timing.json) and `ddd-video-judge` before publishing, or use the auto loop.
- Every `upload-video` MINTS A NEW walkthrough id, so a link already emailed is frozen on the old cut and silently goes stale. Publishing a correction required a second email. For anything shared with humans, hand out the narrative page (/canopy/ddd/<slug>), not the per-walkthrough URL.
- Harness Tailwind ships utilities but NOT `grid-cols-12` / `col-span-*` — a 3-column layout silently stacked. Use explicit grid styles in workflow render_code.
- Ranking demo subjects by NET metric gain surfaces noise (a child bouncing 14.5→13→12→15.4 has a big delta and reads as broken data). Penalise week-over-week drops so the default subject is a monotonic climb.
